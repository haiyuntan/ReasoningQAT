# Verify and reproduce

Run `python verify_results.py` from this directory. It needs only Python's standard library and checks published SHA256 values, 48 cases/model, shared candidate/token identities, and exact D replay receipts. Read RESULTS.zh.md and metrics/ABCD_summary.json for results. No GPU or model download is needed to inspect or verify these published artifacts.

For a full model rerun, copy this artifact directory into a project root as `observation_calibration_v3_20261111/`. Source scripts derive ROOT from that directory's parent. They rely on the original project asset layout, not a turnkey standalone install: BF16 REAL-Prover and P3/P4/P6 exports with exactly the hashes in manifests/models.json; the pinned state_tactic_pairs dataset (revision91bb339e61ff045d3ebf97cd94d1df1d755dd745); miniF2F-valid at REAL-Prover revision3e5987dc1009a7addc935bcd7b4ae777738a0848; the frozen tokenizer and retrieval identities; Lean4.16.0 with matching Mathlib/Jixia/REPL; and an isolated Python3.11 environment. The runtime snapshot is included; Lean binaries, source data, model weights, full environments, U/hidden tensors and caches are excluded. Package versions and actual source identities are recorded in manifests.

The original launcher copies an existing local observation environment, so another machine must build its own isolated prefix and adapt those local preparation paths. Use the frozen V_real_states.jsonl/discovery_pilot.jsonl for paired forwards; rerunning collection against a new retrieval service is a different input snapshot and must be recorded separately. Recreate A_basis.pt and per-model vector/block caches with score.py before replay.py/analyze.py. Do not treat missing caches as zero error. The included final receipts are historical evidence: use a NEW output directory/remove only copied receipts when rerunning; never overwrite originals or let the launcher skip work based on published DONE receipts.

The protocol and runtime override are distinct: configs/protocol.json defines the scientific sample/layer/action choices; configs/runtime_resources.json raises duty/memory limits. P0 was completed with the original resource profile; P3/P4/P6 retained batch1 after failed batch-parity tests. No original training, evaluation or retrieval environment should be modified by reproduction.
